## v1.0.2 — 修复下拉菜单被下方内容遮挡/覆盖

- 现象：设置页所有 BaseSelect 下拉展开时，选项被下方设置行/卡片盖住（回收站自动清空、自动锁定、剪贴板、语言、备份间隔等全部）
- 排查结论：
  - 直接机制：`.settings-row:hover` 的 transform 建立层叠上下文，把行内菜单(z-index 300)困在行内，后续兄弟行按 DOM 顺序盖住下拉
  - 更深层：WKWebView 合成层绘制异常会加剧"下拉与其他动效重叠/拉伸覆盖"（纯 CSS z-index 修不全）
- 最终方案（组件级，一处处修全部）：BaseSelect 菜单 Teleport 到 body + fixed 定位（与 CtxMenu 同款策略），脱离弹窗/滚动容器的 overflow/transform 影响；SidebarNav 的 btn-dropdown-menu 同款处理
  - 视口钳制：上下展开自适应、高度/横向按视口钳制、scroll/resize rAF 重定位
  - 层级确认：菜单 300 > 弹窗遮罩 200（浮于弹窗上），< confirm 400（确认弹窗仍盖住下拉）✓
- 过程记录：AI 先落过一版 `.settings-row:hover/:active/:focus-within/:has(.base-select.open)` z-index 抬升的 CSS 修复（settings.css），Teleport 方案落地后该修复已无作用，已 git checkout 还原，避免双机制并存
- 版本：1.0.1 → 1.0.2（npm run version:set，11 处校验一致）；构建由用户执行

## 修复本地打包签名私钥注入失效（并入 v1.0.2 发布）(2026-09-02)

- 报错：`A public key has been found, but no private key. Make sure to set TAURI_SIGNING_PRIVATE_KEY`
- 根因链：`.env.local` 用 `~/.tauri/lockpass-updater.key` → Node existsSync 不展开 `~` → 包装器静默跳过（旧版无警告）→ 兜底分支设置 `TAURI_SIGNING_PRIVATE_KEY_PATH`，但 tauri-cli 2.11.4 打包签名只认 `TAURI_SIGNING_PRIVATE_KEY`（值可为内容或文件路径），`_PATH` 仅 tauri signer 子命令支持 → 打包器找不到私钥
- 参考 fastenerTradeWorkbench 同款实现修复：候选路径 `~` 前缀展开（os.homedir()）；兜底改为内联注入；指针缺失显式告警；未找到私钥打印指引
- fastenerTradeWorkbench 的同名脚本仍存在"兜底设 _PATH 无效"死角（因 ~ 展开未触发过），建议后续同步
- 验证：node --check 通过；冒烟测试注入成功（来自 .env.local 指针展开后命中）
- 版本：保持 v1.0.2 不升版（用户决定：v1.0.2 未发布，脚本修复并入同版日志）
