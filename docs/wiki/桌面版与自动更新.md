# 桌面版与自动更新

> 面向桌面版用户与维护者：架构差异、自动更新原理、签名体系与发布流程。桌面版基于 **Tauri v2**（Rust）封装，覆盖 Windows 与 macOS，前端与浏览器版共用同一份 `dist/` 产物。

## 架构差异：数据存储

macOS 的 WKWebView 在 `tauri://` 协议下 IndexedDB 存在兼容性问题，桌面版改用**应用数据目录文件存储**：

- `src/core/file-store.js` 与 IndexedDB **同接口**透明替换，业务层无感知
- 数据为整体加密文件（加密机制见 [[安全架构]]）
- 支持数据目录绑定与文件同步（设置 → 文件同步）

## 构建命令

```bash
npm run tauri:dev     # 桌面开发模式（自动启动 Vite dev server）
npm run tauri:build   # 构建桌面安装包（含 updater 签名）
npm run make-dmg      # (macOS) 生成 .dmg
```

## 自动更新原理

基于 Tauri 官方 updater 插件 + GitHub Releases：

1. 桌面版启动 5 秒后后台检查 `releases/latest/download/latest.json`
2. 发现新版本 → 自动下载（进度见 设置 → 关于 → 应用更新）
3. **minisign 签名校验**通过后安装；篡改 / 错配的更新包会被拒绝
4. Toast 提示并弹确认「立即重启」；可在设置关闭自动检查、改为手动

> [!NOTE]
> 更新清单随 GitHub Release 的 Draft 状态发布：**Publish Draft Release 后用户才可达**，此前清单 404 属预期。

## 更新签名体系

- 私钥本地保管：`~/.tauri/lockpass-updater.key`（生成命令：`npm run tauri -- signer generate -p 密码 -w ~/.tauri/lockpass-updater.key`）
- 公钥内嵌 `src-tauri/tauri.conf.json`；**私钥丢失需轮换公钥并全量重装，务必备份**
- CI 所需 Secret：`TAURI_SIGNING_PRIVATE_KEY`（私钥全文）与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`（生成密钥时设置的密码）

### 本地构建签名（.env.local）

`npm run tauri:build` 由包装器 `scripts/with-updater-key.mjs` 接管，密钥注入规则：

1. 已设置内联 `TAURI_SIGNING_PRIVATE_KEY`（CI 场景）→ 原样透传
2. 未设置 → 读取项目根 `.env.local` 的 `TAURI_SIGNING_PRIVATE_KEY_PATH`（支持 `~` 展开）与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，将私钥文件内容注入为内联变量
3. 都没有 → 给出指引后由 Tauri 报缺钥错误

> [!WARNING]
> `tauri build` 的打包签名**只认 `TAURI_SIGNING_PRIVATE_KEY`**（值可以是私钥内容，也可以是私钥文件路径）；`TAURI_SIGNING_PRIVATE_KEY_PATH` 仅 `tauri signer` 子命令支持。请始终通过 `npm run tauri:build` / `npm run build` 走包装器。

## 发布流程

1. 推送 `v*` 标签（如 `v1.0.2`）或手动触发工作流
2. GitHub Actions 构建三平台产物并自动生成 `latest.json`
3. 进入 Releases **Publish Draft Release** → 桌面端用户可自动更新

| 平台 | 产物 |
|------|------|
| Windows | NSIS 安装包（.exe）+ MSI（.msi） |
| macOS | .app 压缩包（.zip）+ .dmg |

> [!NOTE]
> v1.0.10 及更早的安装包无更新能力，需手动安装一次 v1.0.11+，此后即可自动升级。
