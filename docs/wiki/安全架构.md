# 安全架构

> LockPass 的安全模型围绕三条原则：**零网络、原生加密、最小暴露面**。本文说明加密链路、数据存储与威胁边界，帮助你评估其安全性。

## 加密链路

主密码通过密钥派生生成 AES-256-GCM 密钥，数据整体加密后落盘：

```text
主密码 → PBKDF2(SHA-256, 100000 次迭代, 32 字节盐值) → AES-256-GCM 密钥
数据   → AES-256-GCM 加密（随机 12 字节 IV）          → 密文存储
```

- 加解密全部基于浏览器原生 **Web Crypto API**，不引入第三方密码库（算法可审计、无供应链风险）
- 迭代次数与盐值随库存储；导入加密文件时使用文件内自带参数，向后兼容
- 解锁后的会话密钥只存在于内存与 `sessionStorage`，锁定即清除

## 数据存储模型

| 数据 | 存储位置 | 加密状态 |
|------|----------|:--------:|
| 密码条目 / 回收站 / 标签注册表 | IndexedDB（浏览器）或应用数据目录文件（桌面版） | 已加密 |
| 主密码 | 不存储 | — |
| 盐值 / 迭代次数 | 存储元数据区 | 明文（无敏感性） |
| 会话密钥 | sessionStorage / 内存 | 解锁期间存在 |

> [!NOTE]
> 浏览器版与桌面版数据相互独立；桌面版通过 `file-store.js` 以同接口透明替换 IndexedDB。跨形态互通见 [[导入导出与迁移]]。

## 安全特性

| 特性 | 说明 |
|------|------|
| 零网络请求 | 核心功能完全离线；可选联网功能（自动检查更新）默认可关闭 |
| 自动锁定 | 无操作超时（1/5/15/30 分钟/从不）自动锁定 |
| 剪贴板清除 | 复制密码后自动清除（10/30/60 秒可配置） |
| 内存清理 | 锁定时清除内存与 sessionStorage 中的明文 |
| CSP 限制 | 桌面版启用严格 CSP，无远程脚本 / 样式 |
| 输入转义 | 所有用户输入经 HTML 转义，防 XSS |

## 威胁模型与边界

| 风险 | 说明 | 防范措施 |
|------|------|----------|
| XSS 攻击 | 恶意脚本窃取内存明文 | 仅在受信任环境使用，避免可疑浏览器扩展 |
| 浏览器漏洞 | 被入侵的浏览器可能读取内存 | 保持浏览器更新 |
| 本地文件泄露 | 设备被盗 / 被入侵 | 系统登录密码 + 磁盘加密（FileVault / BitLocker） |
| 主密码遗忘 | 无法恢复 | 牢记或妥善保管（见 [[常见问题]]） |

## 开发者安全规范（摘要）

- 禁止外部 CDN、远程字体、外部 API（离线优先）
- 禁止 `localStorage` 存储敏感数据；禁止 `eval` / `new Function`
- 密码相关操作只用 Web Crypto API；敏感信息不打印到控制台
- 危险操作（销毁保险箱、清空回收站）需二次确认
