## 一、执行摘要

**总体评价**：LockPass 的产品底子扎实——功能盘点实测具备 50+ 项，密码管理器的核心闭环（增删改查、回收站、标签、关联密码、二维码、扩展自动填充、本地加密、自动更新）完整可用，且有一批值得保留的体验亮点（剪贴板安全链路、危险操作确认链、空状态分场景、触屏/横屏打磨）。本次审计发现的问题集中在**「最后一公里」闭环缺口**与**「洞察型功能」缺失**两类。

**关键数字**：合并去重后 P1 级发现 **10 项**、P2 级 **24 项**、P3 级 **25 项**；另有 **18 项 ≤15 分钟快速改进**。其中 4 项 P1 属「数据完整性/安全语义」级别，建议优先处理。

**方法论说明**：三路并行审计（功能设计 / 操作流程 / 用户体验）+ 主线交叉核验。操作流程维度的 Agent 在报告撰写前超时，其证据由主线补做完成；全部 P1 断言经主线二次实证（file:line 复核），其中 1 项被交叉核验纠偏（详见 4.2）。

## 二、P1 级发现（10 项）

### 2.1 危险确认框默认焦点落在「确认」键（键盘误操作放大器）

- **证据**：`src/core/utils.js:270-272` — `confirm()` 弹窗创建后 `okBtn.focus()`，焦点默认落在红色确认键；Enter 直接触发确认。
- **影响**：删除/回滚/销毁/清空回收站等全部危险操作，键盘连按 Enter 即执行——与「危险操作应默认焦点取消」的通行实践相反。
- **建议**：danger 弹窗默认焦点改为取消按钮；Enter 触发取消而非确认。

### 2.2 编辑模式无未保存保护，且草稿「只写不读」

- **证据**：`EntryEditorModal.vue:241-256`（onMounted 仅新建分支调用 `loadDraft()`，编辑分支从不恢复）；`:82` 每次按键 `persistDraft()` 写入 `lockpass_draft_edit_*`，但该键在编辑模式下从不读回——只写不读的死数据。Esc 或误点遮罩即静默丢弃全部修改。
- **影响**：长表单录入一条失误全损；与新建流程（有草稿恢复）行为不一致。
- **建议**：编辑分支 onMounted 恢复草稿（比对 updatedAt 提示「检测到未保存的修改」）；或至少 Esc/关闭前弹确认。

### 2.3 app 条目「公钥」行的复制值与标签不符

- **证据**：`DetailPanel.vue:222` — `<SecretFieldRow label="公钥" :value="entry.password" copy-mode="value" />`：公钥行显示与复制的实际是 `entry.password` 字段；配合 `useVault.js:1007` copyPassword 的 app 分支（`val = entry.appId || entry.password`），「密码」行复制的却是 App ID。
- **影响**：复制结果与所见标签不符——对密码管理器是信任级缺陷。
- **建议**：app 类型的字段行标签与取值逐一对照（appId/privateKey/password 三行各归其位）。

### 2.4 二维码替换导入产生「孤儿密码历史」

- **证据**：`QrImportModal.vue:207-214` — 替换 = `splice` 删除旧条目再插入新条目；旧条目 ID 关联的密码历史（`history[oldId]`）随之成为孤儿——**旧版本的明文密码仍滞留在不可见的加密存储中**，且不参与任何展示/清理。
- **影响**：数据完整性与安全卫生双重问题（应删未删的敏感明文）。
- **建议**：替换时迁移或显式清除 `history[oldId]`；同时检查收藏状态与 createdAt 语义。

### 2.5 导入去重策略四入口三种行为

- **证据**：批量导入（ImportModal）逐条询问替换；CSV 拖入（import-bridge.js:157）**静默跳过**重复；二维码导入询问替换但删除语义有缺陷（2.4）；扩展同步无去重交互。
- **影响**：同一份数据从不同入口导入结果不同，用户无法建立稳定预期。
- **建议**：统一为「询问替换」+ 提供全局「跳过全部重复」选项；去重键（标题+用户名）在文档中明示。

### 2.6 密码健康审计缺失

- **证据**：功能盘点（对照 spec.md 与组件清单）——无弱密码/重复密码/旧密码检测仪表盘，用户对「哪些密码该换」零可见性。
- **建议**：P1 功能补齐：解锁后一次性本地扫描（纯前端计算，不出网），输出弱密码/重复/超期未改三类清单，入口放侧边栏。

### 2.7 密码强度算法「纯熵误判」

- **证据**：强度算法仅按字符池×长度计算熵，`Aa1!Aa1!` 这类模式化弱口令会得高分（强度条与真实风险脱节）。
- **建议**：引入常见口令字典 + 模式检测（重复/键盘序列/年份），降权显示。

### 2.8 修改主密码无强度把关

- **证据**：修改主密码流程未复用创建时的 8 位校验与强度条（`useVault.js:344/393` 仅创建模式有校验）。
- **建议**：改密复用同一强度组件；至少补最低长度校验。

### 2.9 TOTP 两步验证缺失

- **证据**：功能盘点——无 TOTP 字段与验证码生成。作为密码管理器的核心竞争能力（1Password/Bitwarden 标配）。
- **建议**：列入路线图（字段 + 30s 动态码 + 复制验证码按钮）；数据模型预留 `totpSecret` 字段。

### 2.10 忘记主密码无自救路径

- **证据**：锁屏/认证组件无任何找回/提示入口；唯一路径 = 销毁保险箱重建（数据全失）。离线加密的架构下这是合理的安全设计，但**产品层面应主动告知**。
- **建议**：锁屏加「忘记主密码？」入口 → 说明「无恢复可能」并引导走「从备份文件恢复」或「销毁重建」流程，管理预期。

## 五、各维度详述

### 5.1 功能设计（Agent 01）

- **盘点**：50+ 项功能全部实现并可用，覆盖六大条目类型（网站/服务器/数据库/AI/应用/其他）、密码历史（5 版）、标签体系、关联密码（同 IP/域名/账号）、回收站、二维码分享导入、浏览器扩展自动填充（本地 HTTP 通道）、自动备份快照、自动更新。
- **亮点**：剪贴板安全链路（复制→倒计时清除→muted 告知）、扩展零密码出应用（脱敏列表+按需解密）、数据全本地不出网。
- **缺口与一致性**：见 2.4/2.5/2.6/2.7/2.8/2.9 与 subagent_01.md（P1×5 + P2×10 + 一致性 11 条）。
