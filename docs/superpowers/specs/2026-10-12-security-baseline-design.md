# LockPass 下一阶段方向决策：收尾 + 安全基线

> 日期：2026-10-12 ｜ 基线版本：v1.1.7 ｜ 状态：已与用户对齐并批准执行

## 背景

功能矩阵已满（见 README 功能清单：TOTP、健康审计、旅行模式、浏览器扩展、局域网同步、桌面生物识别、PWA、自动备份等全部落地）。头脑风暴围绕「接下来做什么」展开，候选归为三条主线：

- **A 收尾 + 安全基线**：落盘上轮遗留改动、KDF 加密参数收尾、macOS 生物识别端到端验证
- **B 分发与上手门槛**：Apple 开发者签名（解决 Gatekeeper 拦截 + 生物识别 entitlement 前提）、浏览器扩展上架 Chrome Web Store / AMO
- **C 效率与新能力**：扩展输入框自动建议、Passkey 凭据管理、条目附件、Bitwarden/KeePass 导入格式、Tauri 2 移动端

## 决策

**选定 A**。理由：产品成熟期加新功能的边际价值下降，把已有能力送到真实场景的价值上升；A 内各项成本低、确定性高；签名（主线 B 的核心）与生物识别验证天然耦合，留待证书到位后一并推进。

## 子决策与理由

1. **KDF 方案：PBKDF2 600k，SHA-256 算法不变**。放弃 SHA-512 变体（GPU 抗性收益不抵兼容复杂度，YAGNI）；放弃 Argon2id（需第三方 WASM，直接违反 AGENTS.md「密码相关操作必须使用 Web Crypto API，不使用第三方库」的安全规范，且动的是全仓库审计最严格的加密层）。
2. **旧库升级策略：显式动作 + 新库新默认；不做解锁时静默重加密**——安全产品里数据被悄悄改写的观感差，且无必要。
3. **代码现状盘点**（比讨论时预想完成度高）：
   - `src/core/crypto.js` 已有 `DEFAULT_ITERATIONS = 600000`（OWASP 2023 基线）与 `LEGACY_ITERATIONS = 100000`（旧数据兜底）
   - 新建保险箱已写 600k（`useVault.js`）
   - 修改主密码已用新盐 + 600k 重加密（`ChangePwModal.vue`，「升级到 DEFAULT_ITERATIONS 以获得更强保护」）——隐式升级路径已存在
   - **真实缺口仅两项**：①设置里无可发现的显式升级入口（不改主密码的旧库用户无法升级）；②README/spec 仍写「100000 次迭代」，文档过时
4. **A3 挂起**：用户暂无 Apple 开发者证书且暂不购买。生物识别全链（enroll → 生物验证 → unlock）从未在签名构建上跑通（ad-hoc 构建必返 `ENTITLEMENT_ERR`），做成 `docs/passkey.md` 里随时可执行的验证清单；证书同时是主线 B 的杠杆点，未来一并决策。
5. **版本**：A1 两批遗留落盘按规范**不推进版本号**（同日同模块追加）；A2 新增设置「升级加密参数」属功能增强 → **v1.1.7 → v1.2.0（MINOR，用户批准）**。

## 未选方向的去向

- 扩展自动建议（C1）：使用频率最高的触点升级，可作为签名等待期的并行小项目
- Apple 签名 + 扩展上架（B）：待证书决策后启动，届时顺带回归 A3 验证清单
- Passkey / 附件 / 移动端（C2）：工程量大，待 A/B 完成后再评估
