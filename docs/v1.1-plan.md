# LockPass v1.1.x 升级计划

> 基于 v1.0.x 功能完备后的产品方向脑暴（2026-09-29），经代码核查确认已实现/未实现状态后整理。
>
> **状态同步（2026-09-29）**：本节标注已对照实际代码与 `docs/version/RELEASE-v1.1.md` 复核更新。实际发布与下方建议版本号存在映射错位：**v1.1.0 实际交付**的是原计划 v1.1.1（健康仪表盘）+ v1.1.2（密码短语 + 过期提醒）+ 扩展 UI 美化；**原计划 v1.1.0 的 TOTP** 代码已完整落地但未记入发布日志。各节标题中的版本号均为原始计划编号，实际状态以各项「状态」标注为准。
>
> **状态同步（2026-09-30）**：v1.1.1 发布——Phase 1 的三个收尾缺口全部关闭（TOTP QR 扫码导入接线、密码 + TOTP 组合复制、列表卡片过期警示）；备份导入（.vault/.json）改为「同类型 + 同标题」覆盖合并。Phase 2 三项仍全部未动工。
>
> **状态同步（2026-10-01）**：Phase 2 剩余两项落地——① 旅行模式（条目级 `sensitive` 标记 + 侧边栏开关，列表/搜索/导出/QR 分享/扩展桥全出口过滤）；② 浏览器扩展自动捕获（submit 监听 + 登录成功启发式 + 浮层确认 + ExtBridge 入库去重）。③ 密钥文件双因素仍为半成品：底层模块已就位（`src/core/keyfile.js` + `CryptoUtils.composeMaterial/deriveKeyMaterial`），但解锁/创建流程与设置页 UI 尚未接线。Phase 3 除 WebAuthn macOS 单端外均未动工。
>
> 核心原则不变：**离线优先 · 安全 · 简洁**

## 一、当前功能基线（v1.0.x 已完成）

| 类别 | 功能 |
|------|------|
| 核心安全 | AES-256-GCM 加密、PBKDF2 密钥派生、剪贴板自动清除、自动锁定 |
| 条目管理 | 6 种条目类型、自定义字段（7 种类型 + 6 套模板）、密码历史回滚（5 版本） |
| 组织检索 | 标签体系（颜色 + 图标）、拼音首字母搜索、收藏、回收站 |
| 密码工具 | 密码生成器（强度评估）、关联密码（同域名/同账号）、Markdown 备注渲染 |
| 数据流转 | QR 加密分享、CSV/.vault 导入导出、浏览器扩展自动填充（MV3） |
| 多端体验 | Tauri 桌面版（Windows/macOS）、PWA、移动端适配（底部导航 + 滑动操作） |
| 个性化 | 暗色/亮色/跟随系统 + 6 主题色、中英文双语、27 个键盘快捷键 |
| 备份恢复 | 自动备份提醒 + 加密快照、文件同步（File System Access API） |
| 桌面增强 | 生物识别解锁（macOS only）、自动更新（minisign 签名校验）、本地文件存储 |

## 二、v1.1.x 升级项

### Phase 1 — 安全能力升级（v1.1.0 ~ v1.1.2）

> 目标：从「密码存储」进化为「密码安全工作台」，建立与云密码管理器的差异化壁垒。

#### 1. TOTP 双因素认证集成 `v1.1.0`

**状态（2026-09-29 核查）**：✅ 已实现 —— `src/core/totp.js`（RFC 6238/4226，`window.TOTPUtils`，含 `parseOTPAuthURI`/`buildOTPAuthURI`/`validateSecret`）、`src/composables/useTotp.js`（动态码 + 倒计时）、详情页动态码 + 进度环（`DetailPanel.vue`）、编辑器手动录入密钥（`EntryEditorModal.vue`）。缺口（已于 v1.1.1 全部关闭，2026-09-30）：QR 扫码导入 otpauth:// URI 已接线（`QrImportModal.vue` 上传 / 粘贴 / 拖拽 / 摄像头四条入口自动绑定条目）、「密码 + TOTP 组合复制」已实现（`DetailPanel.vue` 组合复制按钮，走剪贴板自动清除链路）。

**描述**：在条目中绑定 TOTP 密钥，详情页实时显示 6 位动态码 + 30 秒倒计时圆环，一键复制。

**技术路径**：
- 新增 `src/core/totp.js`：HMAC-SHA1 自实现（Web Crypto API），RFC 6238 TOTP 算法
- 支持 `otpauth://totp/...` URI 解析（复用现有 QR 扫描流程导入）
- 支持手动输入密钥（Base32 解码）
- 数据模型：条目新增 `totp` 字段 `{ secret, issuer, account, period, digits, algorithm }`
- 详情页：动态码显示区 + 倒计时进度环（CSS conic-gradient）
- 复制按钮：密码和 TOTP 分别复制，或组合复制 `密码 + TOTP`

**依赖**：无，纯前端实现，spec §8 已规划

**工作量评估**：核心算法 ~200 行 + UI 组件 ~150 行 + 测试向量验证

#### 2. 密码健康仪表盘 `v1.1.1`

**状态（2026-09-29 核查）**：✅ 已实现并随实际 v1.1.0 发布 —— `src/core/audit.js`（`auditVault`，weak/reused/empty/stale/expired 五类 + 加权评分）+ 设置弹窗「安全报告」标签页（`SettingsModal.vue`，含逐条定位跳转），UI 已闭环。

**描述**：全局安全评分（0-100），分项展示弱密码 / 重复密码 / 空密码数量，点击可跳转定位问题条目。

**技术路径**：
- 新增 `src/core/audit.js`：遍历所有条目，计算安全指标
  - 弱密码：复用 `PasswordGenerator.calcStrength()`，< 40 bits 为弱
  - 重复密码：跨条目比对 password 字段哈希值
  - 空密码：password 为空字符串的条目
  - 长期未更新：超过 90/180/365 天未修改的条目（可选）
- 安全评分算法：按条目加权，弱密码扣分最重，重复次之
- UI：设置页新增「安全报告」入口，或侧边栏独立图标
  - 环形评分图 + 分项柱状图
  - 点击分项展开问题条目列表，点击跳转编辑

**依赖**：无，纯前端计算

**工作量评估**：审计逻辑 ~150 行 + UI ~200 行

#### 3. 密码短语生成器 `v1.1.2`

**状态（2026-09-29 核查）**：✅ 已实现并随实际 v1.1.0 发布 —— `src/core/generator.js` 的 `generatePassphrase()` + `src/core/eff-wordlist.js`（EFF 7776 词）+ `PasswordGeneratorModal.vue` 模式切换与实时熵值。

**描述**：密码生成器新增「密码短语」模式，从 Diceware 词表生成易记高强度的词组密码。

**技术路径**：
- `src/core/generator.js` 新增 `generatePassphrase(options)` 方法
- 内置 EFF 英文词表（7776 词，~40KB）+ 中文词表（可选）
- 配置项：词数（4-8）、分隔符（`-` / `.` / 空格 / 自定义）、首字母大写
- 熵值计算：`log2(wordlist_size) * word_count`
- UI：密码生成器面板新增模式切换（随机字符 / 密码短语）

**依赖**：upgrade-design §9.1 已规划 `EFF_WORDLIST`

**工作量评估**：词表文件 ~40KB + 生成逻辑 ~80 行 + UI 调整 ~50 行

#### 4. 密码过期提醒 `v1.1.2`（可与密码短语同期）

**状态（2026-09-30 核查）**：✅ 已实现（v1.1.1 补齐最后一项）—— 编辑器日期字段（`EntryEditorModal.vue`）、详情页过期徽章（`DetailPanel.vue`）、解锁 Toast 提醒（`useVault.js` `afterUnlock()`）、设置页提前警告天数 7/14/30/60/90（`SettingsModal.vue`）、列表卡片过期/即将过期警示角标（`AppShell.vue`，复用 `VaultAudit.getExpiryStatus`，同警告天数口径）均已落地。

**描述**：条目支持设置「过期日期」，到期前在列表和详情页显示提醒标识。

**技术路径**：
- 数据模型：条目新增 `expiresAt` 字段（ISO 日期字符串，可选）
- 编辑器：日期选择器（`<input type="date">`），支持「永不过期」
- 列表卡片：过期/即将过期（30 天内）条目显示警告图标 + 颜色标识
- 设置：全局过期提醒开关 + 提前天数（7/14/30 天）
- 解锁时检查：如有过期条目，Toast 提醒「X 条密码已过期，建议更新」

**依赖**：无

**工作量评估**：数据模型迁移 ~30 行 + UI ~100 行

### Phase 2 — 体验与生态（v1.1.3 ~ v1.1.5）

> 目标：降低使用摩擦，拓展使用场景。
>
> **状态（2026-10-01 核查）**：旅行模式与扩展自动捕获已完成；密钥文件双因素半成品（底层模块就位、流程未接线）。

#### 5. 旅行模式 `v1.1.3`

**状态（2026-10-01）**：✅ 已实现 —— 条目编辑器「标记为敏感」开关（条目级 `sensitive`，`useVault.saveEntry` 落盘）；侧边栏「旅行模式」开关（localStorage `lockpass_travel_mode` + 「已隐藏 N 条」指示）；出口过滤：列表/搜索/回收站（`getFilteredEntries`）、侧边栏统计（`computeSidebarStats`）、`.vault`/CSV 导出（`ExportModal`）、二维码分享（`QrShareModal` + `selectEntry` 拦截关联跳转）、扩展桥（`ExtBridge.setEntriesProvider` 过滤，`get-password` 同步失效）；详情页盾牌徽标（`DetailPanel.vue`）。

**描述**：条目可标记为「敏感」，开启旅行模式后所有敏感条目从列表、搜索、导出、扩展填充中隐藏。

**技术路径**：
- 数据模型：条目新增 `sensitive: boolean`（注意：与自定义字段的 `sensitive` 掩码标记区分，这是条目级别）
- 编辑器：开关组件「标记为敏感」
- 旅行模式状态：localStorage 存储 `travelMode: boolean`
- 过滤层：`useVault` 的条目列表计算属性增加旅行模式过滤
- 安全边界：导出、QR 分享、扩展填充均检查该标记
- UI：侧边栏顶部「旅行模式」开关 + 状态指示

**依赖**：无

**工作量评估**：过滤逻辑 ~50 行 + 各出口检查 ~80 行 + UI ~60 行

---

#### 6. 浏览器扩展自动捕获 `v1.1.4`

**状态（2026-10-01）**：✅ 已实现 —— `extension/content.js` submit 监听（form 范围提取用户名 + 已填密码，LockPass 页面经 `data-lockpass-app` 标记跳过）→ `extension/background.js` 按 tab 内存暂存 15s（`LP_CAPTURE_PENDING/CHECK`，登录成功判定 = 页面跳转或密码框消失）→ 页面浮层「保存到 LockPass？」（保存/忽略/20s 自动收起）→ `LP_CAPTURE_SAVE` 经 `lockpass-bridge.js` 转发页面 `ExtBridge`（令牌校验）→ `useVault.handleExtensionCapture`：精确主机名 + 同用户名去重（同密码跳过 / 异密码更新并记录历史 / 未命中新建网站条目），结果回传浮层提示。桌面版 HTTP 通道暂未接入捕获。

**描述**：扩展检测到用户在网页上成功登录时，弹出「保存到 LockPass？」提示。

**技术路径**：
- `extension/content.js`：监听表单 submit 事件，提取域名 + username + password
- 检测登录成功：submit 后页面跳转 / 出现密码字段消失 / URL 变化
- 弹出保存提示：扩展 popup 或页面内浮层
- 通过 ExtBridge 发送给主应用保存为新条目
- 去重：检查是否已存在同域名 + 同用户名的条目

**依赖**：现有 ExtBridge 通信机制

**工作量评估**：扩展侧 ~200 行 + 主应用接收 ~50 行

---

#### 7. 密钥文件双因素 `v1.1.5`

**状态（2026-10-01 核查）**：🔶 半成品 —— 底层已就位：`src/core/keyfile.js`（`window.KeyFileUtils`：生成 / 解析 / 校验 / 指纹）+ `CryptoUtils.composeMaterial/deriveKeyMaterial/deriveKeyBytesMaterial`（PBKDF2(password ‖ keyFileBytes) 派生链路）已提交（8c1745f）。缺口：`hasKeyFile` meta 标记、创建/解锁流程接线（AuthView 选 .key 文件）、设置页「启用密钥文件」入口均未实现。

**描述**：支持 `.key` 密钥文件 + 主密码双因素解锁保险箱，提升离线场景安全性。

**技术路径**：
- 密钥文件生成：设置页「启用密钥文件」→ 生成 32 字节随机密钥 → 下载 `.key` 文件
- 密钥派生改造：`deriveKey(password + keyFileBytes, salt, iterations)` → 拼接后哈希
- 解锁流程：先选择 .key 文件（浏览器 file input / Tauri dialog）→ 再输入主密码
- 数据模型：meta 新增 `hasKeyFile: boolean`
- 安全提示：密钥文件丢失将无法解锁，启用时强制确认

**依赖**：无

**工作量评估**：密钥管理 ~100 行 + 解锁流程改造 ~80 行 + UI ~100 行

## 三、已排除项（与产品原则冲突）

| 功能 | 排除原因 |
|------|---------|
| P2P / 自托管云同步 | 与零网络原则冲突，README 已明确排除 |
| AI 语义搜索 | 需嵌入模型，纯前端无法离线运行 |
| 紧急访问包 | 低频场景，涉及异步信任链，实现复杂 |
| 密码共享保险箱 | 需服务端协调，偏离个人工具定位 |
