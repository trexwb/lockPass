## 一、当前功能基线（v1.0.x 已完成）

| 类别 | 功能 |
|------|------|

### Phase 1 — 安全能力升级（v1.1.0 ~ v1.1.2）

> 目标：从「密码存储」进化为「密码安全工作台」，建立与云密码管理器的差异化壁垒。

#### 1. TOTP 双因素认证集成 `v1.1.0`

**状态（2026-09-29 核查）**：✅ 已实现 —— `src/core/totp.js`（RFC 6238/4226，`window.TOTPUtils`，含 `parseOTPAuthURI`/`buildOTPAuthURI`/`validateSecret`）、`src/composables/useTotp.js`（动态码 + 倒计时）、详情页动态码 + 进度环（`DetailPanel.vue`）、编辑器手动录入密钥（`EntryEditorModal.vue`）。缺口（已于 v1.1.1 全部关闭，2026-09-30）：QR 扫码导入 otpauth:// URI 已接线（`QrImportModal.vue` 上传 / 粘贴 / 拖拽 / 摄像头四条入口自动绑定条目）、「密码 + TOTP 组合复制」已实现（`DetailPanel.vue` 组合复制按钮，走剪贴板自动清除链路）。

**描述**：在条目中绑定 TOTP 密钥，详情页实时显示 6 位动态码 + 30 秒倒计时圆环，一键复制。

**技术路径**：
- 新增 `src/core/totp.js`：HMAC-SHA1 自实现（Web Crypto API），RFC 6238 TOTP 算法

- 数据模型：条目新增 `totp` 字段 `{ secret, issuer, account, period, digits, algorithm }`
- 详情页：动态码显示区 + 倒计时进度环（CSS conic-gradient）
- 复制按钮：密码和 TOTP 分别复制，或组合复制 `密码 + TOTP`

**依赖**：无，纯前端实现，spec §8 已规划

**工作量评估**：核心算法 ~200 行 + UI 组件 ~150 行 + 测试向量验证

#### 2. 密码健康仪表盘 `v1.1.1`

**状态（2026-09-29 核查）**：✅ 已实现并随实际 v1.1.0 发布 —— `src/core/audit.js`（`auditVault`，weak/reused/empty/stale/expired 五类 + 加权评分）+ 设置弹窗「安全报告」标签页（`SettingsModal.vue`，含逐条定位跳转），UI 已闭环。

**描述**：全局安全评分（0-100），分项展示弱密码 / 重复密码 / 空密码数量，点击可跳转定位问题条目。

**技术路径**：
- 新增 `src/core/audit.js`：遍历所有条目，计算安全指标
  - 弱密码：复用 `PasswordGenerator.calcStrength()`，< 40 bits 为弱
  - 重复密码：跨条目比对 password 字段哈希值
  - 空密码：password 为空字符串的条目
  - 长期未更新：超过 90/180/365 天未修改的条目（可选）
- 安全评分算法：按条目加权，弱密码扣分最重，重复次之
- UI：设置页新增「安全报告」入口，或侧边栏独立图标
  - 环形评分图 + 分项柱状图
  - 点击分项展开问题条目列表，点击跳转编辑

**依赖**：无，纯前端计算

**工作量评估**：审计逻辑 ~150 行 + UI ~200 行

#### 6. 浏览器扩展自动捕获 `v1.1.4`

**状态（2026-10-01）**：✅ 已实现 —— `extension/content.js` submit 监听（form 范围提取用户名 + 已填密码，LockPass 页面经 `data-lockpass-app` 标记跳过）→ `extension/background.js` 按 tab 内存暂存 15s（`LP_CAPTURE_PENDING/CHECK`，登录成功判定 = 页面跳转或密码框消失）→ 页面浮层「保存到 LockPass？」（保存/忽略/20s 自动收起）→ `LP_CAPTURE_SAVE` 经 `lockpass-bridge.js` 转发页面 `ExtBridge`（令牌校验）→ `useVault.handleExtensionCapture`：精确主机名 + 同用户名去重（同密码跳过 / 异密码更新并记录历史 / 未命中新建网站条目），结果回传浮层提示。桌面版 HTTP 通道暂未接入捕获。2026-10-08 安全审查追加：凭据/条目投递只发给按浏览器提供的 `sender.url` 命中应用地址白名单（`isTrustedAppPageUrl`）且带 `data-lockpass-app` 标记的页面桥（不再全量广播），`file://` 双击用法默认拒绝、需在扩展弹窗显式信任本地页面；保存 payload 取后台待确认记录而非页面提交；结果等待改为按 `requestId` 独立登记以支持并发保存。2026-10-08 补齐桌面版通道：桌面端无可用页面桥时，扩展改走本地 HTTP `POST /capture`（Bearer 令牌 + 已解锁才受理），Rust 侧只登记 id/时间/状态的待确认槽位（**不保留明文**，凭据经 `lockpass:capture-request` 事件交给窗口），`GET /capture/status?id=` 一次性领取结果，用户在桌面窗口确认后才经 `handleExtensionCapture` 入库并由 `server_capture_report` 回报；监听注册收敛到 `useVault` 模块作用域，多次实例化不会重复弹确认框。同日再补三点：待确认槽位改为最多 4 个按 id 独立登记（多标签页同时保存不再互相顶掉，超出上限挤掉最旧并让该次轮询得到 404 失败提示）、扩展等待期间每 20s 真走一次扩展 API 顶回 MV3 后台 30s 空闲回收、浮层加 50s 兜底避免后台被杀时卡在「保存中…」；`src-tauri/src/server.rs` 的 `route` 事件发射抽成可注入闭包后补了 13 项 `cargo test`，含在真实 `127.0.0.1` 随机端口上跑通 `/capture` 与 `/capture/status` 两条腿（鉴权、409 未解锁、载荷校验、槽位登记与事件、一次性领取、TTL 过期、并发独立回报、上限淘汰、锁定即丢弃，以及配对→领令牌→用该令牌成功捕获的串联）。

**描述**：扩展检测到用户在网页上成功登录时，弹出「保存到 LockPass？」提示。

**技术路径**：
- `extension/content.js`：监听表单 submit 事件，提取域名 + username + password
- 检测登录成功：submit 后页面跳转 / 出现密码字段消失 / URL 变化
- 弹出保存提示：扩展 popup 或页面内浮层
- 通过 ExtBridge 发送给主应用保存为新条目
- 去重：检查是否已存在同域名 + 同用户名的条目

**依赖**：现有 ExtBridge 通信机制

**工作量评估**：扩展侧 ~200 行 + 主应用接收 ~50 行

## 三、已排除项（与产品原则冲突）

| 功能 | 排除原因 |
|------|---------|
| P2P / 自托管云同步 | 与零网络原则冲突，README 已明确排除 |
| AI 语义搜索 | 需嵌入模型，纯前端无法离线运行 |
| 紧急访问包 | 低频场景，涉及异步信任链，实现复杂 |
| 密码共享保险箱 | 需服务端协调，偏离个人工具定位 |
| 密钥文件双因素（原 Phase 2 §7 / v1.1.5） | 2026-10-08 决策移除：第二因子收益不抵代价——密钥文件丢失即保险箱永久锁死（离线无找回路径），浏览器版每次刷新还须重新选择文件，与「双击即用、低摩擦」定位冲突。同日完成源码清理：删除 `src/core/keyfile.js`（`window.KeyFileUtils`）与 `CryptoUtils.composeMaterial/deriveKeyMaterial/deriveKeyBytesMaterial`（均为零调用方，删后 `vite:build` 与解锁/重载解密链路回归通过） |
| 演示模式（原 Phase 3 §12） | 2026-10-08 决策移除：属获客型功能，与本产品的安全定位冲突——演示态需要在同一页面里维持「未解锁的真保险箱不可达」这条边界，所有写路径（`saveVault` / 导入 / 改主密码 / 文件同步 / 扩展桥捕获 / `.vault` 导出）与自动锁屏、旅行模式、会话恢复语义都要额外打标分流，任一处漏判就可能把示例数据写成真实数据或让演示态被误认为已解锁。当前用户来自主动搜索密码管理器，不存在需要预置数据转化的冷启动漏斗 |
| HIBP 泄露检测（原 Phase 3 §9） | 2026-10-08 决策移除：是本产品唯一需要联网的功能，与「离线优先 · 零网络请求」底线直接冲突（k-anonymity 虽只上报 SHA-1 前 5 位，仍属把用户口令摘要交给第三方）；且本地已覆盖同类需求——`core/audit.js` 的弱密码 / 复用 / 空密码 / 长期未更新 / 过期五类审计 + 密码强度熵值估算已给出同样的行动建议。真要做也只能是「默认关闭 + 手动触发」的低频入口，收益不抵定位代价 |
| 活动时间线视图（原 Phase 3 §10） | 2026-10-08 决策移除：价值已被现有能力覆盖——列表卡片与详情页均展示 `updatedAt`（`AppShell.vue`、`DetailPanel.vue`），编辑历史可回滚 5 版，「长期未更新」条目在安全报告 stale 分类里已按时间聚合可跳转定位。个人密码库量级下「按时间浏览」不是主动线需求，单独做一个时间刻度视图属重复建设 |
| 卡片显示自定义（原 Phase 3 §11） | 2026-10-08 决策移除：与「简洁」定位冲突——卡片字段与顺序的偏好需要持久化 + 设置页配置 + 移动端/桌面端两套布局分别适配，而当前卡片固定展示（标题 / 账号 / 域名 / 标签 / 修改时间 / 收藏 / 过期角标）信息密度已够，用户没有表达过此诉求。属高成本低收益的可选型功能 |
