> 评审维度：功能流程 / 操作便捷性 / UI 设计 / 用户体验（含安全与可维护性交叉项）
> 评审依据：前端开发规范 Skill + AGENTS.md 项目规范 + docs/spec.md

## 1. 总体结论

整体质量高于同类个人项目平均水准：架构分层清晰（core / composables / components / styles 职责边界严格）、设计令牌体系完整（色彩 / 圆角 / 阴影 / z-index 全变量化）、暗色优先 + 浅色主题 + 6 强调色 HSL 驱动、模态框有焦点陷阱、安全设计意识强（剪贴板自动清除、锁定清内存、防抖合并写盘、明文导出警示）。

本次评审发现 **2 个 P1、12 个 P2、13 个 P3** 问题，无 P0 阻塞项。核心矛盾集中在：**锁定时明文滞留清理不彻底（history / 草稿）、键盘可达性覆盖不全、规格文档与实现失真**。

| 维度 | 评分 | 一句话结论 |
|------|:----:|-----------|
| 功能流程 | 8.5/10 | 认证/CRUD/回收站/历史回滚/导入导出/备份链路完整健壮，个别边界静默失败 |
| 操作便捷性 | 8/10 | 27 个快捷键 + 实时搜索 + 草稿恢复很顺手，缺列表键盘导航 |

## 2. 问题清单（按严重度分级）

### 2.1 P1 — 应尽快修复

#### P1-1 锁定/登出未清空密码历史（内存明文滞留）

- **位置**：`src/composables/useVault.js` `lockVault()`（L591-610）、`logout()`（L612-634）
- **现象**：R2/S1 修复清空了 `entries / tagDefs / tags / deleted / selectedEntry`，但 **`vaultState.history` 未清空**。history 快照（`snap`）包含修改前的**明文密码 / root 密码 / 私钥**（HISTORY_FIELDS 含 password / privateKey / root）。锁定后明文继续驻留内存直至下次解锁被覆盖。
- **影响**：与自身「锁定时清空明文滞留」的安全目标直接冲突；共享电脑场景下，锁定后可通过调试器读取残留明文。
- **修复建议**：`lockVault()` 与 `logout()` 中补 `vaultState.history = {}`。

#### P1-2 编辑器草稿将明文密码写入 sessionStorage 且锁定不清理

- **位置**：`src/components/modals/EntryEditorModal.vue` `persistDraft()`（L80-90）；`useVault.js` `lockVault()/logout()` 未清理
- **现象**：草稿（含 `fields.password`、`rootPwd`、`privateKey` 明文）持久化到 sessionStorage；仅在保存成功时 `removeItem`。**用户中途锁定或退出登录，草稿仍留在 sessionStorage**（刷新存活，直到关闭标签页）。
- **影响**：违反「敏感信息不放入 localStorage/sessionStorage」安全规范（前端开发规范 §12 / AGENTS.md §3）。锁定 = 安全边界被打破。
- **修复建议**（三选一，推荐 a）：
  - a. `lockVault()/logout()` 时遍历清除 `lockpass_draft_*` 键；
  - b. 草稿不落盘 secret 字段（密码类字段不参与草稿恢复）；
  - c. 草稿加密后存（复杂度高，不推荐）。

## 3. 分维度详评

### 3.1 功能流程（8.5/10）

**做对的**：
- 认证链路健壮：非安全上下文（file:///http）阻断 + 按钮禁用（D9）；绑定目录恢复一次输入完成登录（D1）；恢复后自动切回解锁模式（R5）——边界处理是逐修复打磨过的，注释里 R/D/S 编号可追溯，工程习惯好。
- 数据安全链路完整：PBKDF2 + AES-256-GCM、salt/iterations 存 meta、saveVault 150ms 防抖合并 + resolver 链正确性（R8）、软删除 + 回收站 + 历史回滚（执行即删、回滚不记史）语义严谨。
- 迁移兼容：categories→tagDirs 幂等迁移、旧字段（host/baseUrl/apiKey）读取回退。

**扣分点**：P1-1/P1-2（锁定清理不彻底）、P2-1（编辑静默丢数据）——三者共同模式是「异常路径覆盖不全」，建议补一组锁定态/边界态的专项用例（AGENTS.md 测试清单可加「锁定后检查 history/草稿清空」「编辑已删除条目」两项）。

### 3.2 操作便捷性（8/10）

**做对的**：27 个快捷键且设置内有完整速查表；⌘K 搜索、输入态守卫（isTyping 时不误触）；hash 保持筛选；草稿自动恢复防误关；剪贴板倒计时可视化。

**扣分点**：列表键盘导航缺失（P2-12）导致快捷键体系「上层很全、底层缺一块」；右键菜单承诺未兑现（P2-2）。

### 3.3 UI 设计（8/10）

**做对的**：设计令牌完备（z-index 分层表、rgba 常量提取、断点文档化）；主题系统用 HSL 色相变量驱动 6 强调色 × 深浅主题，一处变量全局跟随；移动端细节到位（iOS 16px 输入防放大、safe-area、触控目标 ≥36px、banner 的 :has() 推让）。

**扣分点**：DetailPanel 复制粘贴式巨型模板（P2-7）是最大维护负债；少量硬编码色（P2-8）；SVG 双体系（P3-4）。

### 3.4 用户体验（7.5/10）

**做对的**：空态分场景文案（回收站/搜索无果/收藏为空各有引导）；错误提示带真实错误信息而非统一文案；QR 容量预检（>2200B 提前拦截、>1800B 光线提示）；绑定目录引导横幅分级文案；备份提醒 + 自动快照的防丢失设计意识。

**扣分点**：a11y 是系统性短板（P2-4/P2-5）——密码管理器用户恰恰是隐私敏感人群，常配合键盘操作；「主密码无法找回」警示缺失（P2-10）对首次创建用户是重大决策信息缺失。

## 5. 修复优先级建议

1. **第一批（安全收口，改动极小）**：P1-1（+1 行）、P1-2（锁定清草稿）、P2-9（编辑器复制走统一链路）。
2. **第二批（体验硬伤）**：P2-4/P2-5（键盘可达性 + aria）、P2-10（主密码警示）、P2-1（编辑丢失提示）。
3. **第三批（规格回写与重构）**：P2-3（spec 更新）、P2-7（DetailPanel 组件化重构，配合下次功能迭代做）。
4. **随版本规划**：P3 系列。

> 依据 AGENTS.md 版本约束：第一批属 Bug 修复（PATCH +1）；第二批中键盘可达性/警示文案属小改进（PATCH），若把 DetailPanel 组件化重构排入则需用户决定是否升 MINOR。
