一、执行摘要

总体评价：底子扎实，问题集中在「最后一公里」闭环缺口与「洞察型功能」缺失。密码管理器核心闭环（增删改查、回收站、标签、关联密码、二维码、扩展自动填充、本地加密、自动更新）完整可用；剪贴板安全链路、危险操作确认链、空状态分场景等属于同类产品中的良好实践。

同时，审计在「用户实际会踩到」的层面发现了值得立即处理的问题：危险确认框默认焦点在确认键（键盘 Enter 直接触发破坏性操作）、app 条目复制值与标签不符、编辑模式无未保存保护、二维码替换导入遗留孤儿密码历史、忘记主密码无自救引导、密码健康类功能（弱密码/重复检测）整体缺失。

二、P1 级发现（10 项）

2.1 危险确认框默认焦点落在「确认」键

证据 src/core/utils.js:270-272：confirm 弹窗创建后 okBtn.focus()，Enter 直接触发确认。删除/回滚/销毁/清空回收站全部中招——键盘连按 Enter 即执行破坏性操作，与「危险操作默认焦点取消」的通行实践相反。

建议：danger 弹窗默认焦点改为取消键；Enter 触发取消。

2.2 编辑模式无未保存保护，草稿「只写不读」

证据 EntryEditorModal.vue:241-256：onMounted 仅新建分支调用 loadDraft()，编辑分支从不恢复；:82 每键 persistDraft() 写入 lockpass_draft_edit_* 但编辑模式从不读回。Esc 或误点遮罩即静默丢弃全部修改。

建议：编辑分支恢复草稿（比对提示），或关闭前确认。

2.3 app 条目「公钥」行的复制值与标签不符

证据 DetailPanel.vue:222：公钥行 value 实为 entry.password；配合 useVault.js:1007 copyPassword 的 app 分支（appId 优先）——「密码」行复制的却是 App ID。复制结果与所见标签不符，对密码管理器是信任级缺陷。

建议：app 类型三行（App ID/公钥/密码）标签与取值逐一对照修正。

2.4 二维码替换导入产生「孤儿密码历史」

证据 QrImportModal.vue:207-214：替换 = splice 删除旧条目再插入，旧条目 ID 关联的密码历史成为孤儿——旧版本明文密码滞留在不可见的加密存储中，不参与展示与清理。

建议：替换时迁移或显式清除 history[oldId]；同步检查收藏与 createdAt 语义。

2.5 导入去重策略四入口三种行为

批量导入逐条询问、CSV 拖入静默跳过（import-bridge.js:157）、二维码询问但语义有缺陷（2.4）、扩展同步无交互。同一份数据不同入口结果不同。

建议：统一「询问替换」+ 全局跳过选项；去重键（标题+用户名）文档明示。

2.6 密码健康审计缺失

无弱密码/重复密码/超期未改检测仪表盘，用户对「哪些密码该换」零可见性。建议解锁后本地一次性扫描（不出网），入口放侧边栏。

2.7 强度算法「纯熵误判」

仅按字符池×长度计熵，Aa1!Aa1! 等模式化弱口令得高分。建议引入常见口令字典 + 模式检测降权。

2.8 修改主密码无强度把关

未复用创建时的 8 位校验与强度条（useVault.js:344/393 仅创建模式有）。建议改密复用同一强度组件。

2.9 TOTP 两步验证缺失

1Password/Bitwarden 标配能力。建议列路线图（totpSecret 字段 + 30s 动态码 + 复制按钮）。

2.10 忘记主密码无自救引导

锁屏无找回入口，唯一路径 = 销毁重建（数据全失）。离线加密下这是合理设计，但应主动管理预期：锁屏加「忘记主密码？」入口 → 说明无恢复可能并引导备份恢复/销毁流程。
