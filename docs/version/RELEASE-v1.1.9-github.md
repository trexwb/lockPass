# LockPass v1.1.9

> 发布日期：2026-10-16 ｜ 主题：浏览器扩展按「IP+端口」精确查找密码，自动填充不再误填

> 本版合并了 v1.1.7 / v1.1.8 / v1.1.9 三个未单独发布的版本（上一个正式发布版为 v1.1.6）。
> 从 v1.1.6 升级的用户请完整阅读本文。

## 🎯 浏览器扩展：IP 地址按「IP+端口」查找密码

以前扩展判断「当前网站」时只看主机名，`http://127.0.0.1:35729/` 与 `http://127.0.0.1:16637/` 会被归为同一个 `127.0.0.1`——两个本地开发服务互相串扰，在 35729 的登录页会弹出 16637 的条目。

**现在：IP 地址的网址带端口一起匹配**，不同端口互不干扰。普通网站仍按域名匹配，语义不变：

- `example.com:8080` 与 `example.com` 视为**同一站点**（域名不区分端口）
- 子域 `a.example.com` 仍匹配 `example.com` 的条目
- 扩展弹窗列表、自动填充建议、登录成功后的「保存到 LockPass」捕获，全部按新口径执行
- 桌面版（本地 HTTP 通道）与网页版（页面桥）行为一致

> ⚠️ 条目里的**网址需要带协议头**（如 `http://127.0.0.1:35729/`）；只填 `127.0.0.1:35729` 无法解析出站点，该条目不会参与匹配。

## 🛡️ 自动填充防误填（v1.1.8 起）

- **搜索表单不再被误填**：`type=search`、搜索语义命名（search / query / keyword / 搜索…）的输入框一律排除，不会因页面监听即时搜索而被无故触发
- **三档填充模式**（扩展弹窗底部切换，自动记忆）：

  | 模式 | 行为 |
  |------|------|
  | 自动填入登录表单（默认） | 检测到登录表单即写入 |
  | 仅提示，点击才填入 | 只弹建议气泡，点条目才填 |
  | 关闭自动填充 | 仅保留扩展图标手动填充 |

- **字段分级**：登录页字段（用户名 / 密码 / 邮箱 / 手机 / 验证码）按上表模式处理；**Token / PIN / 恢复码等敏感字段在任何模式下都只提示、绝不自动写入**，用户点击后才填
- **登录成功后不再自动填**：填完密码观察到页面跳转即停止该页面自动填充；密码框重新出现（登出 / 切换账号）自动恢复
- 中文表单识别增强：关联 `<label>` 文本识别「账号 / 用户名 / 邮箱 / 手机号」等

## 🔁 局域网同步：同一凭证自动归并（v1.1.7 起）

- 同步合并改按「类型自然键」判同：网站=网站地址+用户名、服务器=连接地址+账号、数据库=数据库地址+用户名、AI=服务名+API 地址、应用=标题+App ID、其他=凭证名称
- 同一凭证在对端以不同 id 存在时自动归并，不再同步出重复条目；真实冲突落选的版本进回收站，可一键找回
- 修复同步合并在多副本 / 墓碑场景下的崩溃与静默丢数据缺陷
- 前提不变：两端主密码必须相同，否则引导改用 `.vault` 导出导入

## ⬆️ 升级说明

- **桌面版**：本版含 Rust 服务端改动（IP+端口 匹配、同步合并判同），需下载新安装包覆盖升级
- **macOS 首次打开**：ad-hoc 签名仍会被 Gatekeeper 拦截，执行一次 `xattr -dr com.apple.quarantine "/Applications/LockPass.app"` 即可（重装后需再执行一次）
- **Windows**：SmartScreen 提示「更多信息 → 仍要运行」
- **浏览器扩展**：重新下载 zip，或在 `chrome://extensions` 点卡片上的刷新
- **数据无需迁移**：`.vault` 格式不变，现有密码库直接解锁即用

## ⚠️ 已知限制

- IPv6 地址（如 `http://[::1]:8080/`）暂不按端口隔离，仍按主机名匹配
- 条目网址需带协议头（`http://` / `https://`），纯 `IP:端口` 无法解析站点
- 局域网同步两端主密码必须相同；旅行模式开启时不能同步
- 在线版（https 页面）不能作为局域网同步客户端（浏览器混合内容限制）
