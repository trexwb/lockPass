# LockPass v1.1.5

> 发布日期：2026-10-10 ｜ 主题：两台设备在同一局域网内直接同步，一轮结束两边都是最新

## ✨ 新特性：局域网同步服务

以前两台电脑之间要同步，只能「导出 .vault → 复制 → 导入」，且以一台为准。v1.1.5 起可以在局域网内直接同步：

**在 A 电脑（作为服务端）**

1. 侧栏「添加密码」旁的 ▾ → 「同步服务」→ 「开启服务」
2. 选择本机地址（多网卡 / VPN / 热点下可能有多个，选对方能连上的那个）
3. 界面显示 `地址:端口` 与**一次性同步口令**（5 个英文单词）+ 10 分钟倒计时

**在 B 电脑或另一台电脑的浏览器（作为客户端）**

1. 同一入口 → 「连接对端」
2. 填写 A 显示的 `地址`、`端口`、`口令` → 「连接」→ 「开始同步」
3. 四步进度（鉴权 → 拉取 → 合并 → 回写）→ 结果页显示新增 / 更新 / 回收 / 恢复 / 冲突数量

**一轮结束，两台设备都是同一份合并结果** —— 客户端拉到快照后先在本地做双向合并，再把合并结果整包推回服务端。任何一边在两边都改过的条目不会静默覆盖：落选的版本会存进回收站，可一键找回。

## 🔐 关于「同步口令」

- 同步口令是 **6 位数字**（如 `038417`），**不是你的主密码**，界面上也明确写着这一点。主密码一旦变成要念出来、拍下来的东西就不再有保护力。
- 口令一次性有效，10 分钟后失效；**输错 3 次服务立即关闭**。
- **硬前提：两台设备必须使用同一个主密码**，否则无法解密对方数据（会明确提示改用「导出 .vault → 导入」做一次性迁移）。
- 全程只传输密文。同步服务不接触任何明文条目，主密码也永不离开本机。
- 口令只有 6 位，安全性靠的是「必须你手动开启服务 + 只在 10 分钟内有效 + 错 3 次即关闭 + 输对了也仍需主密码才能解开数据」，而不是靠口令本身的长度。这是蓝牙 / Wi-Fi 配对 PIN 的同类用法；如果将来要在公网或长期开放使用，会换回更长的词组口令。

## 🔧 升级与注意事项

- **桌面端需重新打包 / 更新**：本次新增 Rust 同步服务模块（`src-tauri/src/sync.rs`）与 9 条 Tauri 命令。
- **首次开启服务会弹防火墙授权**，这是正常的：服务需要在局域网端口上监听。
- **两台设备必须在同一网段**，且网络没有开 AP 隔离 / 跨 VLAN 隔离。连不上时请优先检查地址是否选对（选错网段是「连不上」的头号原因），或改用手机热点直连。
- **浏览器版只能当客户端**（填对方的地址与口令），不能开启服务 —— 浏览器没有监听端口的能力。用 `file://` 双击打开本地 `dist/index.html` 即可作为客户端使用。
- **手机形态暂不支持**，原因与之前一致：设备的页面来源地址会变会导致数据成孤儿。手机仍请用 `.vault` 导出导入。
- **旅行模式开启时不能同步**（入口置灰）。
- 数据格式不变，无需迁移；未使用本功能时行为与 v1.1.4 完全一致。
