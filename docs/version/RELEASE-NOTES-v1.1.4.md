# LockPass v1.1.4

> 发布日期：2026-10-09 ｜ 主题：浏览器扩展「保存新密码」链路全面修复与增强

## ✨ 新特性

- **保存的条目标题取网页标题**：扩展捕获登录凭据新建条目时，标题优先使用页面 `<title>`（自动清洗控制字符、截断 200 字符），取不到时回退域名，条目列表一眼可辨。
- **SPA 登录即时弹出保存浮层**：单页应用登录后不再需要手动刷新页面——提交后扩展在页面内观察「地址变化 / 密码框消失」，命中即弹「保存到 LockPass？」；登录框内嵌在 iframe 里时，浮层也会出现在页面右上角。

## 🐛 修复

- 修复扩展保存新密码到桌面版始终提示「桌面版 LockPass 返回异常」的问题：
  - 无主机名内嵌登录框（srcdoc / about:blank 等）此前上报空域名被后端拒绝——现在按「帧域名 → 来源页 → 顶层地址」三级解析，条目落在宿主站点域名下；
  - 桌面端确认成功但结果被超时清理误报失败、凭据过期被误报为「返回异常」等三处误报根因；
  - 浮层等待窗口与后台确认等待时间对齐（最长等待期间不会再提前显示失败）。
- 修复「保存过一次（或点过一次忽略）后，同一页面不再弹保存浮层」：每次新的登录提交都会重新询问，符合浏览器密码管理器习惯。
- 修复扩展暂存有效期与页面观察窗贴边导致的偶发不弹窗。
- 桌面版：修复 Tauri capabilities 无效权限项引起的构建失败；本地服务捕获链路异常不再被静默吞掉（新增可见 toast 与仅含形状的 `[capture]`/`[LP_CAPTURE]` 诊断日志，绝不记录凭据内容）。

## 🔧 升级与注意事项

- **浏览器扩展需重新加载**：`chrome://extensions` → LockPass → 重新加载。本次新增 `tabs` 权限（用于顶层地址兜底解析站点身份），Chrome 会提示「读取浏览历史」，确认一次即可；拒绝该权限时内嵌登录框场景的兜底能力会降级。
- **桌面版需重新打包/启动**：Rust 侧载荷与事件新增 `title` 字段（向后兼容：旧版扩展不发 title 时标题回退域名）。
- file:// 打开的本地页面无站点身份，不再弹保存提示（与浏览器自身行为一致）。
- Web 版与桌面版数据格式不变，无需迁移。

### 安装

- **macOS**：打开 `LockPass.dmg`，将 `LockPass.app` 拖入「应用程序」。首次打开若提示「已损坏，无法打开」或「无法验证开发者」，可在终端执行 `xattr -dr com.apple.quarantine "/Applications/LockPass.app"` 解除隔离后重新打开；
- **Windows**：双击 `.msi` 或 `-setup.exe` 按向导安装（WebView2 缺失时安装包会引导下载）；
- **Linux**：`sudo apt install ./LockPass_x.x.x_amd64.deb` 或 `sudo dpkg -i LockPass_x.x.x_amd64.deb`。
