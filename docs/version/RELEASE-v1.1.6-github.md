# LockPass v1.1.6

> 发布日期：2026-10-10 ｜ 主题：两台设备在同一局域网内直接同步，一轮结束两边都是最新

## ✨ 局域网同步服务

以前两台电脑之间要同步，只能「导出 .vault → 复制 → 导入」，且以一台为准。v1.1.6 起可以在局域网内直接同步：

**在 A 电脑（作为服务端）**

1. 侧栏「添加密码」旁的 ▾ → 「同步服务」→ 「开启服务」
2. 选择本机地址（多网卡 / VPN / 热点下可能有多个，选对方能连上的那个）
3. 界面显示 `地址:端口` 与 **6 位一次性同步口令** + 10 分钟倒计时

**在 B 电脑或另一台电脑的浏览器（作为客户端）**

1. 同一入口 → 「连接对端」
2. 填写 A 显示的 `地址`、`端口`、`口令` → 「连接」→ 「开始同步」
3. 四步进度（鉴权 → 拉取 → 合并 → 回写）→ 结果页显示新增 / 更新 / 回收 / 恢复 / 冲突数量

**一轮结束，两台设备都是同一份合并结果** —— 客户端拉到快照后先在本地做双向合并，再把合并结果整包推回服务端。任何一边在两边都改过的条目不会静默覆盖：落选的版本会存进回收站，可一键找回。

同步口令是 **6 位数字**，**不是你的主密码**，界面上也明确写着这一点。口令一次性有效，10 分钟后失效；**输错 3 次服务立即关闭**。

## 🍎 macOS 用户必读：首次打开被拦截怎么解除

macOS 版是 ad-hoc 签名（未配置 Developer ID 证书），首次打开会被 Gatekeeper 拦截，提示：

> 「LockPass.app"已损坏，无法打开。你应该将它移到废纸篓。」

这不是真的损坏，是正常的 Gatekeeper 安全机制。**解除方法：打开「终端」，粘贴执行**

```bash
xattr -dr com.apple.quarantine "/Applications/LockPass.app"
```

然后正常双击打开即可。

**注意事项**

- **只需执行一次** —— 但每次**下载新版本重新安装**后要再执行一次（隔离属性是随下载施加的，不是随应用版本）。
- 如果不是装在 `/Applications`，把路径换成实际位置，例如：

  ```bash
  xattr -dr com.apple.quarantine ~/Downloads/LockPass-macos-aarch64/LockPass.app
  ```

- 也可以不用命令：在「访达」里**右键**点 LockPass.app → 「打开」，弹窗中点「打开」即可。
- Windows 版会看到 SmartScreen 提示，点「更多信息」→「仍要运行」。

## 🔧 同步连不上时怎么排查

两台设备**必须在同一网段**，且网络没有开 AP 隔离 / 跨 VLAN 隔离。连不上时按这个顺序查：

1. **地址是否选对** —— 选错网段是「连不上」的头号原因；多网卡 / VPN / 手机热点下本机有多个地址，要选对端能连上的那个。
2. **macOS 需要「本地网络」授权** —— 若提示被系统拦截：系统设置 → 隐私与安全性 → 本地网络 → 允许 LockPass。**注意：重新构建 / 重装应用后原授权会失效，需要重新勾选一次。**
3. **防火墙** —— Windows 检查防火墙是否放行本程序；首次开启服务会弹防火墙授权，选「允许」。
4. 仍不行可用手机热点让两台设备直连，或退回 `.vault` 导出导入。

> 小提示：`ping` / `nc` 能通 ≠ 应用能连。终端有局域网授权，应用没有 —— 所以「命令行能连上但同步失败」通常正是第 2 条。

## 🔐 关于同步口令

- 6 位数字，**不是主密码**，界面明确标注。主密码一旦变成要念出来、拍下来的东西就不再有保护力。
- **硬前提：两台设备必须使用同一个主密码**，否则无法解密对方数据（会明确提示改用「导出 .vault → 导入」做一次性迁移）。
- 全程只传输密文。同步服务不接触任何明文条目，主密码也永不离开本机。
- 口令只有 6 位，安全性靠的是「必须你手动开启服务 + 只在 10 分钟内有效 + 错 3 次即关闭 + 输对了也仍需主密码才能解开数据」，而不是靠口令本身的长度。这是蓝牙 / Wi-Fi 配对 PIN 的同类用法。

## ⚠️ 使用限制

- **浏览器版只能当客户端**（填对方的地址与口令），不能开启服务 —— 浏览器没有监听端口的能力。用 `file://` 双击打开本地 `dist/index.html` 即可作为客户端。
- **在线版（https）不能当客户端**：浏览器禁止 https 页面访问 http 服务（混合内容）。会直接给出这个提示。
- **手机形态暂不支持**，原因与之前一致：设备的页面来源地址会变会导致数据成孤儿。手机仍请用 `.vault` 导出导入。
- **旅行模式开启时不能同步**（入口置灰）。

## 📦 其他

- 数据格式不变，无需迁移；未使用同步功能时行为与 v1.1.4 完全一致。
- 桌面端需重新打包 / 更新：本版新增 Rust 同步服务模块（`src-tauri/src/sync.rs`）与 9 条 Tauri 命令。
- 修复：二次开启同步服务会崩溃；回写后服务端数据未生效（表现为「同步显示成功、对端没更新」）。
