## v1.0.3 — 修复备份 JSON 导入报「不支持的文件格式」

**现象**：批量导入弹窗选择自动快照 / 同步生成的 JSON 备份（`backups/LockPass-backup-*.json`、`LockPass-vault.json`）时，右下角 Toast 报「不支持的文件格式」。

**根因**：加密备份有两套信封，导入侧只认其一——

| 文件 | format 标记 | 结构 |
|------|------------|------|
| `.vault` 手动导出 | `encrypted` | salt + iterations + iv + data |
| 自动快照 / 文件同步 | `LockPass-file-sync` | salt + iterations + iv + data（同构） |

- `ImportModal.previewVault()` 仅接受 `format === 'encrypted' && data.data` 或明文 `entries`；快照 JSON 两条都不命中 → 落入 else 报错
- 主窗口拖拽导入 `import-bridge.js processFile()` 同样的 `format === 'encrypted'` 判断，同样漏掉快照

**修复**：两处均改为按加密封套结构识别——文件同时含 `salt + iv + data` 即走主密码解密流程，不再依赖 format 标记；解密逻辑不变（PBKDF2 按文件自带 salt/iterations 派生）。预览展示时间回退读取 `updatedAt`（快照无 exportedAt）。

**改动文件**：
- `src/components/modals/ImportModal.vue` — previewVault 加密封套结构判断
- `src/core/import-bridge.js` — 拖拽导入同一兼容
- `docs/spec.md` §3.11 — 格式表补 `.json` 行 + 识别方式说明
- `README.md` — 导入小节补快照说明；更新日志新增 v1.0.3

**验证**：
- 谓词行为测试：vault 导出 / 快照 / 明文 entries / 垃圾 JSON / 旧版无 iterations 五种形态分类全部符合预期
- `npm run vite:build` 通过
- `npm run version:check` 全部 11 处一致

**版本**：v1.0.2 → v1.0.3（PATCH，Bug 修复），`npm run version:set 1.0.3`

**注意**：改动留在工作树未提交，由用户决定是否 commit。

## v1.0.4 — 回滚功能优化：「密码历史」升级「修改历史」

**需求**（用户 4 点）：① 除密码外任意修改都生成记录；② 点击回滚先确认防误操作；③ 回滚成功删除被执行记录防重复执行；④ 回滚不新增记录（回滚不是编辑）。

**数据模型变更**：
- 旧：`history[id] = [{ password, at }]`（仅存旧密码）
- 新：`history[id] = [{ at, snap, fields }]` —— snap 为修改前可回滚字段深拷贝（title/entryType/username/password/url/port/notes/tags/root/appId/privateKey），fields 为本次变更字段列表；旧版仅密码记录兼容（只恢复密码，展示「旧版记录 · 仅密码」）

**实现要点**（`src/composables/useVault.js`）：
- `recordEntryHistory(id, prev, next, at)` 替代 pushHistory：diffKeys 全字段比较（histEq 深比较数组/对象、nullish 归一），有差异才入史；与最新一条快照全等去重；上限仍 5
- `rollbackEntry(id, at)` 替代 rollbackPassword：先 `window.Utils.confirm` 确认弹窗（danger，提示覆盖字段与不留副本）→ 应用快照 → 删除被执行记录（空则删 key）→ 单次 saveVault 原子落盘；**不再回写当前状态为新记录**
- `snapDiffers(entry, snap)`：回滚按钮禁用态 + 同版本守卫（旧版记录只比密码）
- favorite/showPassword 状态位不入史
- 导出 API 更名并新增 snapDiffers / describeHistoryFields

**UI**（DetailPanel.vue）：区块改名「修改历史」，每行 = 时间 + 掩码密码 + 变更字段说明；entries.css 加 .history-changed。

**验证**：16 项行为模拟断言通过（首轮 2 个失败为测试脚本断言笔误，修正后全绿）；vite:build 通过；version:check 11 处一致。

**版本**：v1.0.3 → v1.0.4。⚠️ 按规范本变更属功能增强、MINOR 需用户决定；AI 仅自增 PATCH（1.0.4），如需 v1.1.0 一句话即可 version:set。

## v1.0.5 — 修复每次写入都报「本地文件同步失败：e.getFileHandle is not a function」

**现象**：任何写入操作（保存条目等，doSave 每次都触发 FileSync.syncNow）弹红色 Toast「本地文件同步失败：e.getFileHandle is not a function」，保存本身成功。

**根因**：存储的目录句柄退化为无方法普通对象。FileSystemDirectoryHandle 无法经 JSON 序列化还原（桌面版 DBUtilsFile 的 meta.json / 任何文本迁移场景会把句柄写成 `{kind,name}`），引擎升级也可能使旧句柄失配；syncNow 照常调用其 getFileHandle → 抛错 → 每次写入必弹 Toast 且永不自愈。

**修复**：
- `file-sync.js`：新增 `isUsableDirHandle()` + `ensureUsableDirHandle()` 自愈式获取——句柄无 getFileHandle 方法时自动解绑（clearDirHandle + 清 lp_sync_bound）、warning Toast 仅一次，返回 null 让后续写入按未绑定静默跳过；syncNow 改走自愈入口
- `backup.js` 浏览器快照分支同样改走自愈
- `SettingsModal.vue`：状态区识别失效态显示「目录句柄失效，请重新绑定」/「句柄失效 · 需重绑」；settings.css 补 .tag-warning

**验证**：8 项行为断言通过（正常/损坏/清除后静默/未绑定/重绑恢复）；vite:build 通过；version:check 一致。

**版本**：v1.0.4 → v1.0.5（PATCH，Bug 修复）

## v1.0.6 — Windows 绑定目录问题加固（用户补充复现：win 下绑定软件根目录后必现）

**复现链路**：Windows 桌面运行 → `window.__TAURI__` 注入异常（file-store 早退）→ 桌面被误判为浏览器 → 设置面板出现「绑定目录」入口 → 用户绑定后 WebView2 句柄经 JSON 落盘 meta.json 丢光方法 → 每次写入 syncNow 报 getFileHandle not a function。

**加固**：
- `file-store.js`：`__TAURI__` 缺失时用 `__TAURI_INTERNALS__.invoke` 兜底桥接（Tauri v2 IPC 底层入口恒在），桌面永远走文件存储模式，绑定入口不再暴露
- `file-sync.js bindDirectory()`：Tauri 环境硬拒绝（双信号 FileStore.isTauri / __TAURI_INTERNALS__），提示「桌面版数据已由本地文件自动保存，无需绑定同步目录」
- `SettingsModal.vue`：两处桌面判定同步升级为双信号

**验证**：6 项环境分支断言通过；vite:build 通过；version:check 一致。

**版本**：v1.0.5 → v1.0.6。已损坏状态的清除依赖 v1.0.5 ensureUsableDirHandle 自愈（首次写入自动解绑 + 提示一次）。

## v1.0.7 — Windows 桌面启动 404（需刷新）复发修复 + Tauri 环境判定统一收口

**现象**：Windows 桌面版打开显示 Edge 风格 404 错误页（找不到 http://tauri.localhost/），点「刷新」才能进入——即 v1.0.2 修过的问题复发。

**统一根因（今日三轮问题串成一条线）**：该用户 Windows 环境 `window.__TAURI__` 全局注入缺失。
- sw-register.js 单信号判定失效 → tauri.localhost 上注册 PWA SW → 旧 SW 拦截首屏 → 404
- file-store.js 同判失效 → 桌面伪装浏览器 → 绑定入口暴露 → 句柄 JSON 落盘退化 → v1.0.5 的 getFileHandle 报错
- 即：v1.0.3~v1.0.6 五轮其实都在收拾这一个根因的不同后果

**修复**：
- 新增 `src/core/tauri-env.js`（main.js 最先 import）：双信号探测，`__TAURI__.core.invoke` 直连，缺失时回退恒存在的 `__TAURI_INTERNALS__.invoke` 并警告，挂载 `window.LockTauri`
- 四个消费方全部收口读 LockTauri：file-store / sw-register / tauri-bridge / tauri-server-bridge
- sw-register：桌面清残留提前到脚本求值期执行（不等 load），缩小旧 SW 干扰窗口；browser 分支逻辑不变
- 桥内 `T.webview/T.event` 等 UI 增强改为可选感知原生全局，兜底模式下优雅跳过

**验证**：环境分支断言 6/6；vite:build 通过；version:check 一致。

**版本**：v1.0.6 → v1.0.7

**给用户的关键提示**：装上本版后第一次打开若仍 404，手动刷新一次（清残留需要一次应用运行期）；之后每次启动正常。若需彻底一次性恢复，可先卸载重装（或清除 WebView2 用户数据目录）。
