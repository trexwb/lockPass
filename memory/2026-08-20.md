## v1.0.1：Tauri 本地文件存储 API（15:34 完成）

### 背景
用户指出 Tauri 桌面版无法使用浏览器 File System Access API 做本地文件同步，需要新增 Tauri API 实现本地文件存储。

### 改动
- **src-tauri/src/lib.rs**：新增 5 个 Rust 命令（invoke_handler 注册）：
  - file_store_write(relative_path, contents) — 写文件，自动建父目录
  - file_store_read(relative_path) — 读文件
  - file_store_exists(relative_path) — 存在判断
  - file_store_delete(relative_path) — 删文件（不存在静默）
  - file_store_data_dir() — 返回数据根目录
  - 数据根目录 = app_data_dir（macOS: ~/Library/Application Support/com.lockpass）
  - safe_join() 路径穿越防护：拒绝绝对路径/.. /空路径/\0
- **js/file-store.js**（新模块，index.html 中位于 database.js 之后）：
  - window.FileStore：Rust 命令薄封装
  - 文件版 DBUtils：与 IndexedDB 版完全同接口（openDB/dbGet/dbPut/dbDelete/dbGetAll/dbClear/deleteDatabase + STORE_META/STORE_VAULT），Tauri 环境自动替换 window.DBUtils，业务代码零改动
  - 存储结构：meta.json（按 key 索引）+ vault.json（按 id 索引）
  - Promise 队列串行化写操作，防并发写丢数据
  - 浏览器环境自动降级（不替换 DBUtils），不影响 Web 版
- **js/settings.js**：refreshFileSyncStatus / refreshDataInfo 增加 Tauri 分支——显示数据目录路径，隐藏「绑定目录」按钮
- **test/test-file-store.mjs**（新）：Node 模拟 Tauri 环境测试脚本，20 项断言全过（读写/覆盖/删除/清空/并发 10 写/删库重建/落盘验证）

## Bugfix: release.yml 删 rust-cache（16:17）

GitHub Actions 首次跑 release.yml 时报错：
```
error: checksum for `itoa v1.0.2` changed between lock files
```

根因：`swatinem/rust-cache` 缓存了 ~/.cargo/registry/（crates.io 下载缓存），但缓存
来源的 registry index checksum 与仓库 Cargo.lock 生成时的 registry 不一致。
常见原因：registry 在两次构建之间更新了某个 crate 的压缩包但 checksum 表未同步。

修复：两个 job 均删除了 `swatinem/rust-cache@v2` 步骤，添加注释说明原因。
GitHub Actions 网络够快，每次构建重新拉取 Cargo 依赖不会慢（~30-60s）。

## Bugfix #2: release.yml 加 cargo 彻底清理步骤（16:34）

删 rust-cache 后仍然报 itoa checksum 错误，persistent。

根因定位：`swatinem/rust-cache` 删除后，CI runner 的 `~/.cargo/registry/` 里
仍残留旧的 stale index。即使不跨 workflow，runner 本身的 $CARGO_HOME 在
多次构建间也是复用的，残留的 index 仍然存在导致 checksum 不一致。

修复：每个 job 构建前主动执行：
  1. rm -rf "$CARGO_HOME/registry"    # 清除旧的 crates.io index（含 checksum 表）
  2. rm -rf src-tauri/target           # 清除旧的 target 编译产物
  3. cargo fetch --locked             # 重新拉取所有依赖，严格按 Cargo.lock checksum 校验
     → 若 checksum 有问题在这里直接暴露，不等到 tauri:build 才报错

两个 job 均加入此步骤。
