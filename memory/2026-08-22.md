| # | 现象 | 根因 | 修复要点 |

## PWA 更新机制修复

### 变更背景

用户提问：PWA「添加到主屏幕」后线上代码更新，手机桌面如何更新。代码审查发现 sw.js fetch 策略为纯「缓存优先」，导致即使新 SW 激活、旧缓存被清理，所有静态资源仍命中（上次 install 写入的）缓存，用户永远拿不到新版代码。

### 修改文件清单

| 文件 | 修改内容 |
|---|---|
| sw.js | fetch 策略重构：导航请求从缓存优先改为网络优先（网络失败回退缓存）；静态资源从缓存优先改为 Stale-While-Revalidate（先返回缓存秒开，后台拉新版写入缓存下次生效）；注释头更新说明完整更新链路 |
| js/sw-register.js | 新增 `controllerchange` 监听：新 SW 激活接管页面时自动 `window.location.reload()` 一次，`refreshed` 标志位防重复刷新 |
| AGENTS.md | 头部「当前版本」v1.0.0 → v1.0.0 |
| SPEC.md | 头部版本行 + 尾部「文档版本」v1.0.0 → v1.0.0 |
| js/app.js | `APP_VERSION` 'v1.0.0' → 'v1.0.0' |
| package.json | version 1.0.13 → 1.0.14 |
| src-tauri/tauri.conf.json | version 1.0.13 → 1.0.14 |
| src-tauri/Cargo.toml | version = "1.0.13" → "1.0.14" |
| sw.js | `CACHE_NAME` 'lockpass-v1.0.0' → 'lockpass-v1.0.0' |
| README.md | 更新日志顶部新增 v1.0.0 条目 |

### 旧策略问题

```
用户打开PWA → 新SW激活 → 删旧缓存 → fetch拦截「缓存优先」
→ index.html / app.js 等仍命中新缓存（上次install预缓存的）
→ 永远返回旧版 → 用户始终看到旧代码
```

### 新策略流程

```
用户打开PWA → 浏览器检查sw.js字节变化 → 新SW安装→skipWaiting→激活
→ 删旧缓存 → controllerchange → 自动刷新页面
→ 导航请求走网络 → 拿到最新index.html → 引用的JS/CSS走SWR
→ 有缓存先返回（秒开）+ 后台拉新版写入缓存
→ 下次打开PWA即完全使用最新代码
```

### iOS 额外注意事项

- iOS Safari 对 sw.js 的更新检查可能受 HTTP 缓存影响（最长 24h），但用户手动刷新 PWA 页面可强制触发检查
- iOS PWA 长期不打开可能被系统清理，再次打开等于全新安装（自动拿最新代码）
- Android Chrome 每次打开 PWA 都检查 sw.js 更新，通常 1 次打开即可更新
