## 修复：自动备份失败（getDirectoryHandle not allowed）

- 现象：移动端解锁后弹错误横幅 "Failed to execute 'getDirectoryHandle' ... not allowed by the user agent or the platform in the current context"
- 根因：浏览器重启后从 IndexedDB 恢复的目录句柄权限为 'prompt'（非 granted），自动快照在无用户手势的解锁流程中调用 getDirectoryHandle(create:true) 被浏览器拒绝
- 修复（backup.js）：
  1. 浏览器分支写快照前 queryPermission({mode:'readwrite'}) 预检，非 granted 返回 reason:'permission'（不支持 queryPermission 的环境跳过预检）
  2. createSnapshot 失败不再弹技术性错误 Toast（自动流程静默）
  3. checkSnapshot 自动流程对 permission/unbound/error 全部静默
  4. SettingsModal backupNow 手动备份按 reason 给可操作提示（permission → 地址栏重新授权或重新绑定目录）
- 验证：vite:build 通过

## 修复：扩展提示"请先打开并解锁 LockPass"(popup 永远未解锁态)

- 根因：ext-bridge.js 的 post() 写成了恒等三元 `__lpExt: MSG_FLAG`(值 = 字符串 '__lpExt')，而页面监听与 lockpass-bridge 均校验 `d.__lpExt !== true` → 页面广播的 ready 消息被桥接脚本拒收 → 扩展永远收不到解锁状态
- 修复：post() 改为 `[MSG_FLAG]: true`（标记值必须为布尔 true，三处校验/发送保持一致）
- 验证：vite:build 通过；grep 确认 4 处 __lpExt 标记一致
- 注意：file:// 双击版还需扩展「允许访问文件网址」权限，否则桥接脚本不注入（popup 提示文案已含排查方向）

## 修复：扩展填充密码框内容为 "undefined"

- 根因：requestPassword 发送 LP_GET_PASSWORD 后立即读 passwordCache——但密码是「页面 postMessage → LP_PASSWORD」异步返回的，sendMessage 的 ok 只代表 bridge 已转发；时序上缓存未就绪 → password = undefined → setNativeValue(undefined) 把 input.value 设为字符串 "undefined"
- 修复（background.js）：
  1. 新增 pendingPassword 等待机制：发请求后挂起，LP_PASSWORD 到达时 resolve（5s 超时报错）
  2. fillCurrentTab 改为等待 requestPassword 结果 + undefined/null 校验
  3. content.js 防御：password 为 undefined/null/'undefined' 字符串时拒绝填充
- 验证：node --check 通过；需重新加载扩展（chrome://extensions → 刷新）后复测
