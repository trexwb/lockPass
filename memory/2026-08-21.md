# 2026-08-21 LockPass 变更记录

## 版本升级：v1.0.2 → v1.0.3（PATCH）

### 变更背景

修复 Tauri 桌面版导出失败 bug：打包成 macOS 应用后点击导出报错 `导出失败：invalid args `options` for command `save`: command save missing required key options`。

根因：`js/tauri-bridge.js` 调用 `plugin:dialog|save` 时参数平铺传入（`{ defaultPath, filters }`），但 Tauri v2 的 `tauri-plugin-dialog` `save` 命令签名要求 `{ options: { defaultPath, filters } }`，缺少 `options` 键导致参数校验失败。

修复：将 `defaultPath` 与 `filters` 包进 `options` 对象。其余插件调用（fs write/read_text_file、clipboard-manager write/read_text）传参结构核验无误，未改动。

## 修复：手机端「两次密码不一致」误报（不升版本号，并入 v1.0.4）

### 变更背景

用户手机端（移动端浏览器）创建保险箱时，两次输入相同密码仍提示「两次密码不一致」。截图确认两个输入框均有内容、提示为红色错误。

根因分析（移动端特有）：
1. 移动端浏览器/密码管理器（iOS 钥匙串、Android Chrome 自动填充、第三方密码管理器）常在页面加载**完成后异步自动填充**，晚于 main.js init 中的同步清空，导致校验时确认框被填入与主密码框不同的值
2. 部分移动端浏览器忽略 `autocomplete="new-password"`，且原模板 `name="new-password"` / `name="confirm-password"` 会强化"密码表单"识别，诱发自动填充
3. 输入框未禁用 autocapitalize/autocorrect/spellcheck，个别输入法可能介入密码框产生不可见差异

### 修改文件清单

| 文件 | 修改内容 |
| --- | --- |
| js/template.js | 两个密码输入框移除 `name` 属性；新增 `autocapitalize="off"` `autocorrect="off"` `spellcheck="false"` |
| js/main.js | 创建场景 init：confirm 框也显式设 `autocomplete="new-password"`；新增 250ms 延迟再清空（仅两框均未聚焦时执行），对抗异步自动填充 |
| js/app.js | 创建分支校验不一致且确认框非空时：清空确认框并聚焦，提示「两次密码不一致，请重新输入确认密码」，引导手动重输消除自动填充干扰 |
| README.md | v1.0.4 条目下追加本次修复记录 |
