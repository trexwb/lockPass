## 修复：手机端「两次密码不一致」误报（不升版本号，并入 v1.0.4）

### 变更背景

用户手机端（移动端浏览器）创建保险箱时，两次输入相同密码仍提示「两次密码不一致」。截图确认两个输入框均有内容、提示为红色错误。

根因分析（移动端特有）：
1. 移动端浏览器/密码管理器（iOS 钥匙串、Android Chrome 自动填充、第三方密码管理器）常在页面加载**完成后异步自动填充**，晚于 main.js init 中的同步清空，导致校验时确认框被填入与主密码框不同的值

3. 输入框未禁用 autocapitalize/autocorrect/spellcheck，个别输入法可能介入密码框产生不可见差异

### 修改文件清单

| js/app.js | 创建分支校验不一致且确认框非空时：清空确认框并聚焦，提示「两次密码不一致，请重新输入确认密码」，引导手动重输消除自动填充干扰 |

## 修复：绑定目录静默覆盖已有同步文件（升级 v1.0.5）

### 变更背景

用户反馈：IndexedDB 不存在（全新状态）时如果绑定数据目录，会导致数据目录中的 `LockPass-vault.json` 同步文件被清空。期望：IndexedDB 为空时绑定数据目录，应把 `LockPass-vault.json` 内容同步进 IndexedDB（用已有文件恢复），而非覆盖。

根因两条：
1. `FileSync.bindDirectory()` 中 `saveDirHandle + LS_SYNC_BOUND` 在恢复检查**之前**执行；且当 IndexedDB 已有数据（如刚创建的空库）时，目录中即使存在 `LockPass-vault.json` 也会直接走 `syncNow()` 用本地数据**静默覆盖**旧文件。
2. 恢复失败时句柄已提前保存，用户后续创建新库会再次触发 `syncNow()` 覆盖旧文件。

### 实现

| 文件 | 修改内容 |
| --- | --- |
| js/file-sync.js | 重构 `bindDirectory()`：先检测目录已有同步文件与 IndexedDB 状态；目录有文件且 IndexedDB 为空 → `restoreFromDirectory` 恢复并绑定；目录有文件且 IndexedDB 已有数据 → `window.confirm` 让用户明确选择（用文件恢复 / 保留当前数据覆盖）；`saveDirHandle + LS_SYNC_BOUND` 移到恢复检查之后，恢复失败不残留绑定标记 |
| js/app.js | 创建保险箱前：若 `FileSync.wasBound()` 但当前本地数据为空（句柄已随库丢失）→ `window.confirm` 提醒优先用「绑定已有数据目录」恢复，防止用户不知情新建空库导致原同步文件无法找回 |

### 关键点

- 绑定目录时**永远不再静默覆盖**目录中已有的 `LockPass-vault.json`
- 恢复失败不保存句柄/不设绑定标记，杜绝后续误覆盖
- 版本号 v1.0.4 → v1.0.5（AGENTS.md / SPEC.md 头尾 / js/app.js APP_VERSION 四处）

### 验证

- js/file-sync.js / js/app.js / js/main.js `node --check` 语法通过

## 修复：手机端横向溢出（升级 v1.0.7）

### 变更背景

用户反馈手机端（竖屏）主界面横向溢出：标题/卡片右边界截断、右侧出现残字（详情面板区域内容），容器宽度超屏未裁剪。

### 根因

CSS 拆分时 `main.css` 导入顺序为 base→layout→entries，`entries.css` 后加载，同特异性下覆盖了 `layout.css` 的移动端规则：
- `#detail-panel { width: 100% }`（≤768/≤480）被 `entries.css` 的 `#detail-panel { width: min(640px, 92vw) }` 覆盖 → 手机端详情面板宽度错误为 92vw（320px 视口下仅 294px）
- `.entry-card { padding: 12px }`（≤480）被 `entries.css` 的 `padding: 14px 16px` 覆盖
- 面板/侧栏关闭状态 `translateX(±100%)` 屏外 fixed 元素在移动端 WebView（iOS/Android）会撑宽可滚动区域，body overflow-x:hidden 只能裁剪不能阻止，产生右侧残字

### 实现

| 文件 | 修改内容 |
| --- | --- |
| css/main.css | 调整 @import 顺序：layout.css 移到 entries.css 之后（响应式覆盖最后生效），改为 base→entries→layout→editor→settings→modal→particles |
| css/entries.css | `#detail-panel` 关闭态加 `visibility: hidden`（transition 含 `visibility 0s linear 0.3s` 延迟隐藏），`.open` 时 `visibility: visible`——屏外 fixed 面板不再参与渲染/滚动，防移动 WebView 撑宽 |
| css/layout.css | ≤768 抽屉 `#sidebar` 同样加 `visibility: hidden`（关闭态）与 `.open` 时 `visible` |
| css/base.css | `html { overflow-x: hidden }`（与 body 双保险） |

### 验证

- 本地 http.server + headless Chrome（playwright-core），375/360/320 视口 + 极端数据（超长标题/账号/标签/备注）：
