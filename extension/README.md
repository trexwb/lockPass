# LockPass 浏览器扩展 — 使用指南

LockPass 密码保险箱的浏览器伴侣扩展（Manifest V3，版本号随主应用同步，当前 v1.1.3）。解锁 LockPass 主应用后，可在任意网站一键填充登录表单；网站登录成功时还会浮层询问是否保存新密码，桌面版通过本机通道配对使用。**主密码不出主应用，扩展零落盘**。

---

## 一、安装

### 1. 加载扩展（Chrome / Edge）

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 右上角开启 **「开发者模式」**
3. 点击 **「加载已解压的扩展程序」**
4. 选择本仓库的 `extension/` 目录

加载成功后，工具栏出现 LockPass 盾牌图标。

### 2. file:// 本地版权限（可选）

如果你使用「双击 `dist/index.html`」的本地版 LockPass：

- 在扩展详情页（`chrome://extensions` → 该扩展 → 详情）开启 **「允许访问文件网址」**

不开此权限，扩展无法与本地文件版 LockPass 通信（popup 会一直提示未解锁）。

### 3. 更新扩展

代码有改动时：`chrome://extensions` → 该扩展卡片点 **「刷新」**（圆形箭头图标），再刷新 LockPass 页面。

## 二、使用流程

1. **打开并解锁 LockPass**（任选一种形态）：
   - 在线版：<https://trexwb.github.io/lockPass/>
   - 本地开发版：`npm run dev` 后访问 `http://localhost:1420`
   - 本地文件版：双击 `dist/index.html`（需开启 file:// 权限）

2. **打开目标登录页**（如 GitHub、某后台系统）

3. 点击工具栏的 LockPass 图标，弹出条目列表（支持搜索标题 / 账号 / 网址）

4. 点击目标条目 → 用户名与密码**自动填入表单**

> ⚠️ 扩展只负责填充，**不会自动提交表单**。填好后会短暂高亮提交按钮，由你确认后手动提交。

### 状态提示

| popup 提示 | 含义 | 处理 |
|-----------|------|------|
| 请先打开并解锁 LockPass 主应用 | 扩展未收到解锁广播 | 打开/刷新 LockPass 页面并解锁（若是 file:// 版检查「允许访问文件网址」） |
| 没有匹配的密码条目 | 密码库为空 | 先在主应用中添加条目 |
| 填充失败：页面未就绪 | 目标网页无扩展响应 | 刷新目标页面后重试 |
| LockPass 页面响应超时 | 解密请求未在 5 秒内返回 | 确认 LockPass 页面保持打开且处于解锁态 |
| LockPass 桌面版未解锁 | 本机服务可达但保险箱锁定 | 在桌面应用解锁，扩展会自动就绪 |
| LockPass 桌面版已解锁 + 底部「连接桌面版 LockPass」按钮 | 桌面通道待授权 | 点该按钮，核对桌面弹窗数字一致后点「允许配对」 |

### 自动捕获：登录成功后保存新密码

1. 在网站提交登录表单、且扩展判定登录成功时，页面右上角弹出「保存到 LockPass？」浮层
2. 点「保存」→ 凭据交给 LockPass 应用（浏览器版走页面桥，桌面版走本地通道），同域名同账号自动去重
3. 浮层回显结果：`已保存到 LockPass ✓` / `已更新该条目密码 ✓` / `条目已存在，无需重复保存 ✓`；取消或忽略则不写入

> 保存动作始终需要你在应用侧确认，扩展不会静默写入密码库；浮层提交的凭据以扩展后台先前登记的待确认记录为准，网页脚本自行 `sendMessage` 的数据不被采信。

### 连接桌面版 LockPass（本地通道）

桌面版是 Tauri 窗口、没有页面桥，扩展改走本机 HTTP：

1. 启动并解锁桌面版 LockPass
2. 点击工具栏 LockPass 图标 → 「连接桌面版 LockPass」→ popup 显示 6 位确认数字
3. 桌面应用弹出配对确认框，**核对数字一致**后点「允许配对」，扩展随即获得访问令牌
4. 之后填充与自动捕获都经桌面端：捕获需在**桌面窗口点「保存」**才入库

| 浮层提示 | 原因 | 处理 |
|---------|------|------|
| 保存失败：请先解锁桌面版 LockPass | 桌面端锁定 | 解锁后重试 |
| 未收到确认：请在桌面版 LockPass 窗口点「保存」 | 45s 内未在桌面端确认 | 到桌面窗口点「保存」，或重新触发 |
| 已在桌面版 LockPass 中忽略 | 桌面端点了取消/忽略 | 无需处理 |
| 未收到保存结果：请在桌面版 LockPass 窗口查看是否已入库 | 后台等待被回收等异常（50s 兜底） | 打开桌面窗口确认是否已入库，再重试 |

> 服务只监听 `127.0.0.1:33555`，不对外网开放；令牌失效（桌面端重置）后需重新配对。

## 三、无痕模式（隐私窗口 / InPrivate）使用

### 1. 启用无痕支持

扩展**默认不在无痕模式下运行**，需手动开启：

| 浏览器 | 路径 |
|--------|------|
| Chrome | `chrome://extensions` → LockPass 扩展 → **详情** → 开启 **「在无痕模式下启用」** |
| Edge | `edge://extensions` → LockPass 扩展 → **详细信息** → 开启 **「在 InPrivate 中允许」** |

开启后，无痕窗口的工具栏会出现 LockPass 图标。

### 2. 无痕模式下的工作机制（重要）

- **扩展后台是普通窗口与无痕窗口共享的**。因此只要**普通窗口的 LockPass 已解锁**，无痕窗口的扩展同样可用——填充请求会由普通窗口的 LockPass 页面完成解密，凭据**不会**写入无痕窗口的任何存储。
- 无痕窗口的 **IndexedDB / sessionStorage 与普通窗口完全隔离**：如果在无痕窗口单独打开 LockPass 在线版，你看到的是一个**全新的空保险箱**，不是你的数据。

### 3. 推荐用法

| 场景 | 做法 |
|------|------|
| 在无痕窗口登录网站 | 先在普通窗口解锁 LockPass，再打开无痕窗口使用扩展填充 |
| 必须在无痕窗口使用 LockPass 本体 | 在无痕窗口打开在线版后，用「导入 .vault」恢复数据（用完即走，无痕关闭后不留数据） |
| 公共电脑 | 无痕模式 + 普通窗口用完即锁定（Ctrl/Cmd + L），或直接关闭窗口 |

### 4. 无痕模式注意事项

- 无痕窗口关闭后，其中所有会话数据（含 LockPass 无痕库）随之清除——**不要**在无痕窗口创建或长期依赖一个保险箱。
- 无痕窗口内使用 file:// 本地版 LockPass，同样需要在扩展详情开启「允许访问文件网址」。
- 无痕模式不改变扩展的安全模型：主密码仍在主应用内存、扩展仍不落盘；但请留意，无痕窗口内的登录态本身即"用完即焚"的定位。

## 四、安全模型

| 项 | 说明 |
|----|------|
| 主密码不出主应用 | 解密只在 LockPass 页面内存进行，扩展仅转发解密结果 |
| 扩展不落盘 | 权限仅 `activeTab` + `storage`（外加 `http://127.0.0.1:33555/*` 本机主机权限）；`storage` 只存桌面配对令牌与「允许本地文件页面接收捕获凭据」开关，**不存任何密码或条目数据**，明文密码只在「请求 → 转发填充」的瞬时内存中出现 |
| 会话令牌 | 解锁时生成一次性令牌（sessionStorage），锁定/登出即失效；所有请求必须携带令牌且来源为同窗口 |
| 定向投递 | 捕获凭据与条目列表只交给浏览器提供、页面无法伪造的 `sender.url` 命中的应用页面（在线版 / localhost:1420 / 127.0.0.1:1420），不再向全部标签页广播；`file://` 本地页面默认拒绝，需显式放行 |
| 桌面通道最小暴露 | 仅监听 `127.0.0.1`，需配对令牌；捕获请求在桌面端只登记待确认槽位（不含明文），60s 过期即丢弃，锁定即清空 |
| 写入需确认 | 自动捕获必须你在应用窗口点「保存」才入库；桌面形态还要在桌面窗口二次确认 |
| 不自动提交 | 填充后不触发提交，避免误操作 |

> 自建部署（非 GitHub Pages / 非 1420 端口）需同步 `background.js` 里的应用地址白名单 `isTrustedAppPageUrl()`，否则捕获与填充的页面桥不会投递到你的地址。

## 五、当前限制（v1.1.3）

- 浏览器版需 LockPass 页面保持打开且处于解锁态（实时代理，不做扩展侧缓存）；桌面版需应用运行且已配对，捕获等待确认上限 45s
- 表单识别基于通用规则（密码框定位 + 常见用户名选择器），复杂/动态表单可能识别失败
- 仅支持单条目点击填充，无自动弹出建议
- 条目列表按标题/账号/网址匹配，无按当前网站自动预筛选
- 同时待确认的捕获最多 4 条，超出会挤掉最早那条（该次浮层会提示失败，重试即可）
- 旅行模式开启时，敏感条目对扩展完全不可见（填充与捕获都不会命中）
